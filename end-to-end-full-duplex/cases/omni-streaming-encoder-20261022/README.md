# 原生 Omni 音频编码器的短块与前缀重算测试

## 范围

在 95 的物理 GPU 5 上，离线加载现有 `Qwen2.5-Omni-3B`，保留权重、音频编码器结构及 `n_window=100`。BF16、eager attention，关闭 Talker，只验证输入端编码的可行性。没有训练、全量解包数据、下载新权重或修改全局依赖。

从 `behavior-sd/test/0000.tar` 顺序选择 8 个不同对话，每个取第一条符合条件的英文话语：3 至 12 秒，无另一主话语重叠、无附和、非打断话语、非方括号非语言事件。选择过程不参考模型输出。这些片段不进入训练。

所有方法先在 22,050 Hz 原波形上按到达时间截断，再重采样到 16 kHz，最后提取 Mel。没有先处理完整未来波形再截取特征。

## 方法

- `offline_full`：整句话的离线编码和转写，作为参考。
- `independent_{100,200,500,1000,2000}ms`：各块独立预处理和编码，拼接 embedding 后交给未训练的 Thinker 转写。
- `prefix_recompute_100ms`：每 100 ms 重算从话语开始到当前的全部已到达波形，记录耗时、旧 embedding 的修订幅度以及部分时刻的快照转写。
- `prefix_append_holdback_{0,200,500,2000}ms`：每次前缀编码后，只追加尚未提交且已达到指定年龄的 embedding；已提交部分不再替换。句尾按已知终点冲刷剩余表示。
- 用首条语音循环构造 2/4/8/16/32 秒输入，仅测长度与耗时关系，不计入质量评价。

转写时用原生 processor 构建匹配的占位符与位置，将真实编码结果注入 `get_audio_features`。另对第一条样本运行真实波形的完整原生 processor/generate，要求与离线 embedding 注入的转写逐字一致，否则终止实验。

这些转写调用使用当前完整 embedding 序列重新生成，**没有实现生成中的 Thinker KV 增量插入，也没有测量 Talker、首音频延迟或全双工行为质量**。

## 实测结果

以下质量数字均来自 `run-04`：8 条语音、合计 51.728 秒、135 个归一化参考词，全部 10 种方法均完成，错误记录为 0。micro-WER 为总词编辑数除以参考词数，不是对每条 WER 求平均。文字标注中的人名与口头停顿会影响结果。

| 输入策略 | 词编辑数 / 135 | micro-WER |
| --- | ---: | ---: |
| 原生整句离线 | 11 | 8.15% |
| 独立 100 ms 块 | 73 | 54.07% |
| 独立 200 ms 块 | 17 | 12.59% |
| 独立 500 ms 块 | 7 | 5.19% |
| 独立 1000 ms 块 | 12 | 8.89% |
| 独立 2000 ms 块 | 11 | 8.15% |
| 每 100 ms 重算前缀，新位置立即提交 | 13 | 9.63% |
| 每 100 ms 重算前缀，延后 200 ms 提交 | 8 | 5.93% |
| 每 100 ms 重算前缀，延后 500 ms 提交 | 9 | 6.67% |
| 每 100 ms 重算前缀，延后 2000 ms 提交 | 11 | 8.15% |

独立 500 ms 块和延后提交在这个小样本上出现更低 WER，不代表显著优于离线，也不据此确定最优块长或延迟。所有方法都复用了未训练的 Thinker；这只是音频表示的代理检查，不是行为 token 或打断能力评估。

第一条样本的原生真实波形对照与 embedding 注入输出完全一致。全部样本的最终前缀与离线 embedding 的相对 L2 都为 0，但这只是最终输入相同的自洽检查，不能证明中途 online 输出等价。

### 速度与长度

`run-04` 的 522 次前缀更新：均值 58.46 ms、P95 76.10 ms、最大 89.97 ms，无一次超过 100 ms。整轮运行约 155.17 秒，峰值 PyTorch allocated CUDA memory 约 11.16 GiB。这不是训练显存预算。

| 已到达前缀长度 | 平均预处理加编码 | 最大值，即 5 次中的 P95 |
| --- | ---: | ---: |
| 2 秒 | 53.30 ms | 56.89 ms |
| 4 秒 | 52.00 ms | 52.34 ms |
| 8 秒 | 52.64 ms | 53.27 ms |
| 16 秒 | 67.07 ms | 73.12 ms |
| 32 秒 | 111.98 ms | 114.32 ms |

长度测试输入为合成循环语音，只测计算开销。完整复核前的 `run-03` 短语音前缀均值 60.51 ms、P95 77.70 ms，32 秒平均 125.69 ms，也显示长前缀越过 100 ms。两次运行负载与时间存在波动，不能按最快的一次承诺实时性。

测试只编码一条音频轨道；双轨编码、Thinker 推理、Talker 与播放尚未计入。不能从这些数字推出双流全链路满足 100 ms。

### 表示修订与时间轴

相邻两次前缀更新对“已经至少有指定年龄”的旧位置进行比较。按更新对加权汇总的平均余弦相似度：未增加年龄限制为 0.94585，至少 200 ms 为 0.97337，至少 2000 ms 为 0.99849。即使超过 2 秒，也不是严格不变；对应平均相对 L2 为 0.04688。块内 attention、重采样边缘及预处理归一化都是需分别审计的因素，本实验没有拆分各因素贡献。

更重要的是，**先前一经提交就冻结的在线 embedding 与最终离线表示并不相同**。例如首条样本中，立即提交策略与离线 embedding 的平均余弦仅 0.38305，延后 200 ms 为 0.75373，延后 2000 ms 为 0.99926，但上述策略在这条上都能完整转写。因此语义保留不等于隐状态等价，不能用 WER 通过来宣称原生缓存接口已经通过。

独立 100 ms 块通常输出 2 个 token，低于连续编码约 25 token/s 的标称速率。例如首条 6.664 秒话语：整句 167 个、独立 100 ms 拼接 134 个、前缀追加 167 个。设计双流时间步时必须保留实际时间戳与有效长度，不能假设每个 100 ms 块都有固定且正确的 2 个音频位置。

### 下一步建议

1. 保留并先冻结原生 encoder，以“每 100 ms 的已到达前缀重算”作为第一版输入实验。立即提交和延后 200 ms 提交均保留为候选，不直接改成独立 100 ms 切块。
2. 实现并验证生成中插入新音频表示的自定义 Thinker 调度；若采用冻结已提交表示的追加策略，训练和推理必须使用同一生成过程。若选择修订旧表示，则要重算受影响的下游缓存，不能只换 embedding 而保留旧 KV。
3. 不无限重算整段会话。下一轮单独验证有限历史/分段策略、原生等价的 Mel 开销优化、双轨批处理，以及叠加语言与语音生成后的预算。这些优化尚未实现，不能将本次结果当作已验证方案。
4. 先扩大到长语音、重叠、用户打断、附和与静音，再评估行为 token。原生 Talker 的真实音频 codec 标签接口仍是独立阻塞，当前测试没有解决它。

## 预处理与诊断记录

编码兼容性和初次完整测试对应 `run-03/report.json`，收紧转写提示的同样本复核对应 `run-04/report.json`。此前诊断尝试保留在服务器：

1. `run-01` 使用 `padding=longest`，在很短的句尾残块上出现 STFT/pooling 错误，主动停止。不能将其成功子集作为最终比较。
2. `run-02` 加入句尾补零与原生波形对照。对照发现 `padding=longest` 与完整 processor 的 `padding=max_length` 在首条样本产生 166/167 个 token 的差异，因此立即终止。
3. `run-03` 按原生 processor 的补零语义提取特征，保持 attention mask；超过默认输入长度时扩展补零长度并禁用截断，不把 32 秒输入偷截为 30 秒。重新运行全部样本和方法。
4. `run-03` 的原生系统提示加“音频后转写指令”在部分整句样本上生成对话回复，而非转写，整句 micro-WER 达到 69.63%。这是转写协议的混淆因素，不能把该数字当作基础语音识别能力或只归因于音频表示。`run-04` 固定转写专用 system、将文字指令放在音频前，对同一批样本和全部方法复核；没有按输出重选样本。两种提示配置一起变化，不区分各自的独立贡献。

不足 40 ms 的句尾残块先重采样，再在右侧补人工零值到 40 ms，以保证卷积和池化有有效输出。这是已知话语终点的测试策略，没有使用未来真实音频，也没有评估终点检测。补零事件保存在 JSON 中。

报告中的耗时包括 Python、重采样、CPU Mel、向 GPU 传输以及同步完成的音频编码，不包括转写生成、收音、网络或播放。这里保留原生大长度补零以确保处理一致性，没有优化这部分开销。

## 复现

实验脚本为 `script/probe_omni_streaming_encoder.py`；在已安装依赖且有足够显存的服务器中运行，输出目录必须尚不存在：

```bash
CUDA_VISIBLE_DEVICES=5 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
TOKENIZERS_PARALLELISM=false OMP_NUM_THREADS=4 \
python script/probe_omni_streaming_encoder.py \
  --model-dir /path/to/Qwen2.5-Omni-3B \
  --dataset-dir /path/to/behavior-sd \
  --output-dir /path/to/new-run --sample-count 8 --strict-transcription
```

`tests/test_probe_omni_streaming_encoder.py` 只验证时间切片、提交计数、端点补零、WER 和统计逻辑，不替代服务器上的真实推理测试。
