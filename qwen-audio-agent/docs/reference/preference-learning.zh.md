# 偏好学习机制

设 `QWEN_AUDIO_PREFERENCE_LEARNING=on` 后，会话结束时会从这一场对话里观察用户画像，
跨会话攒够确认再写进 `USER.md`。默认关闭，因为它每场会话多一次模型调用。

基础开关观察四个字段，取值空间刻意收窄，不自动开启相处偏好：

| 字段 | 说明 |
| --- | --- |
| `occupation` | 职业 |
| `special_skills` | 擅长的技术或领域，最多 6 项 |
| `response_length` | 回答长短，只能是 `brief`、`normal`、`detailed` 之一 |
| `response_style` | 回答风格 |

写入位置是 `USER.md` 的 `## 观察推断` 段，与 `## 用户明确要求` **物理分开**。两段冲突
时明说恒优先。这样划分是为了避免推断内容污染用户自己写下的指令 —— 用户能看到哪些是
他说过的、哪些是系统猜的，也能直接编辑或删掉后者。

### 晋升门槛

一条观察要同时满足两个条件才写进文档：`confirm ≥ 2` 且来自 **≥ 2 个不同会话**。
90 天内没有新确认则 `confirm` 归零。

### 相处偏好学习

`QWEN_AUDIO_COMPANIONSHIP_LEARNING` 默认 `on`，Gateway 启动时自动启用以下三个维度；
无需额外设置，也不要求同时开启基础偏好学习。可显式设为 `off` 关闭。
两项都开启时共用一次观察模型调用，不增加第二次观察调用。
需要 `QWEN_AUDIO_MEMORY_AUTO=on`（默认）以及可用的文本模型凭据
`QWEN_AUDIO_MEMORY_API_KEY` 或 `DASHSCOPE_API_KEY`；自定义模型可设置
`QWEN_AUDIO_MEMORY_MODEL`、`QWEN_AUDIO_MEMORY_BASE_URL`。没有模型时不学习。
自行接管会话观察的 Memory Provider 仍由该 Provider 实现学习，不叠加这条内置链路。

| 字段 | 取值 | 使用范围 |
| --- | --- | --- |
| `support_style` | `listen_first` / `advice_first` / `ask_first` | 用户倾诉时先倾听、先给建议，或先问想要哪种支持 |
| `humor_style` | `no_jokes` / `gentle` / `light_teasing` | 不主动开玩笑、温和玩笑、轻度打趣；正向玩笑偏好仅适用轻松聊天 |
| `checkin_style` | `no_unsolicited` / `occasional` / `contextual` | 不主动追问、偶尔关心、适度自然跟进，限正在聊天且话题相关时 |

这些是回应偏好，不是人格判断、情绪诊断或亲密度。优先级为：**当前明确请求 > 明确长期要求 >
观察推断 > 默认助手风格**。倾诉支持偏好不影响普通任务回答；用户严肃求助或难过时，不因其
平常喜欢打趣就开玩笑。

相处偏好的晋升条件比基础字段更严格：至少 **2 个不同会话**的有效反馈，且首末有效反馈
相隔至少 **24 小时**。同一会话同一维度同一取值只计一次；单纯等待 24 小时不算新证据。
换成相反取值会重新计数，90 天无新反馈会重新积累。新观察在会话结束时处理，晋升后在下一次
建立会话时带入，不在音频播放途中主动改写会话。

例如，在两天的聊天中分别说“你先听我说，别急着给我建议”，可以积累 `listen_first`；
“我能接受你轻轻调侃我”可积累 `light_teasing`。“今天你别拿我开玩笑”仅作用于当下，
即使模型只引用其中一小段，校验也会检查其所在的完整用户发言，不固化为长期偏好。
“以后我倾诉时先听我说”走现有明确长期记忆路径，不必等候推断晋升。

首版采用保守的中文反馈校验：引用必须来自**同一条用户发言**并支持具体取值，排除临时要求、
引用台词、第三方说法、明显疑问与反话。像“这样好多了”这种需要猜测指代的话先不学习。
每个至少有一条新用户发言的会话结束后都会尝试观察；短会话也可以提供证据，但跨会话确认、至少 24 小时间隔和逐字反馈校验的晋升门槛不变。
只读取用户发言，不使用生成的助手文字判断用户是否听到或喜欢某次回复；被打断或未播放的
回复也不能成为认可证据。沉默、继续聊天和聊天时长均不视为正反馈。自然语言校验不是完整
语义理解，复杂表达可能漏收，此时可直接提出明确长期要求。

关心偏好**只影响回复内容**：没有新增主动发声调度器，不按时间或轮数自动插话，不创建提醒，
也不在会话外联系用户。此修改位于 Gateway 的文本决策与记忆层，级联 ASR → LLM → TTS
可以直接使用；不改 TTS，不增加声音情绪识别。

关闭开关会停止新观察和旧候选晋升，但不删除已保存的偏好。可通过现有记忆 API
`GET /api/memory` 查看，使用带文档 revision 的 `PATCH /api/memory` 更正或删除；也可编辑
`USER.md`。API／记忆工具成功修改会清除旧的待确认候选和在途观察权限，保留新的对话学习
能力。直接改文件不会自动清空候选池；需要停止学习时先关闭开关。证据最多保留 3 段用户原话，
每段最多 50 字，并记录判据；不同 `ownerId` 独立保存。默认个人身份不是声纹识别，多人产品
须先接好身份认证，不能让多人共用同一个 `ownerId`。

### 四道结构性防护

模型有时会给出真实的引用、但从引用到结论的推理不成立。这类错误重复采样挡不住 ——
用户每场都说同一句话，模型每次同样误推，计数照样涨到门槛。所以判据放在入池那一刻：

| 判据 | 挡什么 |
| --- | --- |
| `quote_not_from_user` | 引用必须逐字出现在用户轮，挡编造证据、把助手发言当用户偏好、以及自我强化 |
| `value_not_anchored` | 结论的字面成分要能在引用里找到落点 |
| `value_parrots_quote` | 值与引用完全相同 —— 那是复读，不是提取特征 |
| `quote_not_about_interaction` | 交互偏好字段的引用必须指向助手，挡「把内容该多长当成回话该多长」 |

诊断记录写进 `memory-audit.jsonl`，可以事后查某条为什么没被收下。

用户设置方式见[个性化](personalization.zh.md)，Provider 边界见[Memory Provider](memory-provider.zh.md)。
